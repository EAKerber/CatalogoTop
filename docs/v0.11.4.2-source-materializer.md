# v0.11.4.2 — Remote Source Materializer

## Problema observado

O hotfix v0.11.4.1 tornou imagens HTTP(S) elegíveis para o Request Bundle mesmo quando CORS impede o navegador de ler seus bytes, usando `source.mode=remote-url`. Um teste real com um agente externo mostrou a fronteira seguinte: o agente conseguia localizar e visualizar a imagem pela web, mas seu editor de imagens não conseguia consumir essa visualização como pixel source. O contrato de fidelidade corretamente impediu recriar o produto por aproximação.

## Decisão

O Request Bundle v2 mantém `remote-url`, mas passa a incluir `tools/materialize-sources.py` e instruções explícitas no `README.txt`. O helper usa somente a biblioteca padrão do Python e transforma locators remotos em arquivos locais antes da edição.

O helper:

- lê `manifest.json` e nunca o modifica;
- valida o fingerprint `sha256("remote-url:<url>")`;
- aceita somente HTTP(S), sem credenciais e em portas 80/443;
- bloqueia localhost, endereços privados/link-local/não globais e limita redirects;
- limita bytes por fonte e no conjunto;
- identifica PNG/JPEG/WebP/GIF/AVIF por assinatura e SVG somente quando declarado como SVG;
- deduplica por fingerprint;
- grava `sources/materialized/<fingerprint>.<ext>`;
- grava `context/materialized-sources.json` com hash dos bytes, MIME, URL final e jobs associados;
- retorna código não-zero se alguma fonte falhar.

`context/materialized-sources.json` é evidência auxiliar, não uma nova autoridade. `manifest.json`, `requestId`, `jobId`, `placementKey` e `usageSignature` permanecem inalterados.

## Paved path do consumidor

Após extrair o Request Bundle:

```bash
python3 tools/materialize-sources.py .
```

Para `embedded`, o arquivo em `source.path` já é a fonte. Para `remote-url`, o consumidor usa o caminho correspondente no índice materializado. Uma imagem vista em browser/web search não deve ser usada como justificativa para recriação aproximada.

Transformações que podem ser executadas fielmente por ferramentas file-native devem preferir os arquivos locais. Um editor generativo só pode ser usado quando consegue ingerir os pixels reais. Se o ambiente não conseguir materializar bytes ou aplicar a transformação necessária sobre o arquivo, o job deve ser reportado como `capability-blocked`, não aproximado.

## Compatibilidade

- Request manifest continua em versão 2;
- Result Bundle continua em versão 1;
- schema do CatalogoTop continua 7;
- `requestId` não passa a depender do README/helper;
- nenhum endpoint/backend novo é adicionado;
- nenhum proxy genérico de imagens é introduzido.
